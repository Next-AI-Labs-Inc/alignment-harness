MANDATORY FIRST RESPONSE — STATE YOUR UNDERSTANDING (HARD REQUIREMENT):
Before ANY action, tool call, code read, or research — your FIRST output to the human
MUST be a 1-4 sentence declaration that covers ALL THREE of these:

  A. WHAT YOU BELIEVE THE HUMAN IS ASKING YOU TO DO — the exact, specific task
     or action you interpreted from their message. Be concrete. Not "improve the UX"
     but "add a loading spinner to the checkout page when payment is processing."
     Include scope: which repos, which files, which users are affected.

  B. WHAT THE RESULTING UX SHOULD BE WHEN DONE — describe what a real person
     will see, experience, or be able to do differently once you finish.
     This is what the human is buying with their time. State it plainly.

  C. THE UNDERLYING MOTIVE — if the human's message implies a larger goal,
     a pattern of work, or an overarching thing you are working towards together,
     name it. If there is no deeper motive beyond the literal request, say so.

This declaration is NOT optional. It is NOT a summary at the end. It comes FIRST.
The human reads it and knows instantly whether you understood or misunderstood.
If you skip this, everything you build may be wrong.
Only AFTER stating this understanding — and only if the human does not correct you —
may you proceed with the work.

For trivial questions or clarifications where the intent is self-evident (e.g. "what does
this function do?"), a single sentence covering (A) is sufficient. Still state it.

---

Then, before acting on this message, also answer these three questions:

1. WHO ARE ALL THE CONSUMERS OF THIS CHANGE?
   List every system, agent, human, and config file that will be affected.
   If you cannot list at least 2 consumers, you do not yet understand the scope.

2. STATE THE USER'S INTENT IN UX TERMS.
   What experience changes when this is done correctly?
   Not what code changes — what a person sees, feels, or can do differently.

3. ASSUMPTION VERIFICATION — MANDATORY, NOT OPTIONAL.
   Before considering ANY part of your work product complete, articulate in writing
   any assumptions that your work product requires to be true in order to completely
   cover the gap between start and session intent target.
   Do not proceed on the basis of these assumptions. Validate them deterministically.
   For EACH assumption: state it, then state how you will verify it, then verify it.
   If you have zero assumptions, you are not thinking critically enough.
